## 1. 项目是什么

个人自用、本地优先的「计划 → 记录 → 复盘 → AI 分析」工具。

1. 「今日」页统一安排与记录当天计划。
2. 健身、饮食饮水、学习与个人档案分模块记录。
3. 数据按日沉淀成历史台账。
4. AI 只基于用户授权的真实数据写分析，数字由确定性代码算。
5. 数据默认在本机；只有显式开启同步才上传增量副本。
6. 数据可导出、可备份、可恢复、可删除。

不可破坏的产品边界：桌面网页只有 demo / guest，真实 AI 只属于作者自有 Android owner 包；demo 的 AI 内容是部署前固化的只读快照；guest 全 Mock；两者都零 `/api/*`。

## 4. 架构与数据边界

### 4.1 高层结构

```text
浏览器 / Android WebView
  ├─ React + Vite 单页应用
  ├─ 业务写入权威：IndexedDB
  ├─ owner 可选：增量同步 outbox
  └─ owner 可选：真实 AI 请求（Authorization: Bearer psa_…）
          │
          ▼
Nginx :80
  ├─ /            落地页
  ├─ /home.html   产品介绍首页
  ├─ /app/        React web demo / guest
  └─ /api/*       → Fastify 127.0.0.1:3000
                       ├─ 凭据门 → IP 限流 → 日配额
                       ├─ SQLite /var/lib/persist/persist.sqlite  (schema 3)
                       ├─ 快照 /var/lib/persist/backups
                       └─ DeepSeek API
```

### 4.2 数据权威

- 业务记录写入权威是本机 IndexedDB。
- 服务端 SQLite 是开启同步后的可检索副本，不是权威，**也不是备份**。
- 备份主体是服务端规范快照（`VACUUM INTO` + `.sha256` 旁车）。
- 服务端综合分析只读同步上来的实体；结果留在服务端归档，不回写本机。

### 4.3 schema

| 层            | 版本              | 说明                                                            |
| ------------- | ----------------- | --------------------------------------------------------------- |
| App IndexedDB | `schemaVersion=3` | owner / guest 空白初始状态；v2 旧样例按精确指纹清理             |
| Server SQLite | `3`               | v3 新增 `ai_usage`、`ai_calls`（P0 Step 2）；旧代码不读这两张表 |
| 导出格式      | `0.3.0`           | 可导入、兼容旧版本                                              |

### 4.4 AI 请求链路（P0 后的确定顺序）

```text
请求体校验 → Key 就绪检查 → 凭据门 → IP 限流 → 日配额预占 → 上游调用 → 审计落库
```

- 顺序不能随意调换：配额放在 IP 限流之后，避免脚本先刷光当日额度；凭据门在最前，未授权请求不消耗限流与额度。
- 配额预占是「读→判→加一」的**单事务**，失败不退（宁可少放行，不可超发）。
- `/api/chat` 与 `/api/report` **共用同一份额度**——它们花的是同一个 Key 的钱。
- `gate=off` 时仍然计数（归到 `anonymous`），否则回滚门等于把止损一起关掉。

### 4.5 凭据形态与环境变量

| 变量                        | 含义                                                  | 生产当前值           |
| --------------------------- | ----------------------------------------------------- | -------------------- |
| `PERSIST_AI_KEYS`           | `k1:<sha256hex>[,k2:<sha256hex>]`，服务端只存哈希     | `k1:<64 hex>`        |
| `PERSIST_AI_GATE`           | `off` / `warn` / `enforce`                            | `enforce`            |
| `PERSIST_AI_DAILY_LIMIT`    | 每日请求上限，`0` 表示关闭                            | `100`                |
| `VITE_PERSIST_AI_KEY`       | 客户端明文 `psa_<32B base64url>`，**只允许**写在 `app/.env.mobile.local` | 已写入（不入库） |

约定：

- 客户端头固定 `Authorization: Bearer psa_…`；`pst_` 设备令牌一律判错。
- 四种失败形态（无头 / 错前缀 / 未知 keyId / 哈希不匹配）返回**完全一致**的 `401 ai_unauthorized`，不区分原因。
- 凭据表为空时 fail-closed（不是 fail-open）。
- 凭据只在 `build:mobile` 时内联；`vite.config.ts` 硬拦截：非 mobile 模式检测到该变量直接构建失败。
- 轮换必须**多 key 并行**：先加 `k2`，重打 APK，确认新包走通后再删 `k1`。不可直接覆盖 `k1`，否则旧包立刻 401。

### 4.6 前端失败语义

| 服务端返回              | 前端行为                                                     |
| ----------------------- | ------------------------------------------------------------ |
| `401 ai_unauthorized`   | 按既有「AI 不可用」语义回退本地规则 / Mock，并如实标注来源   |
| `429 ai_quota_exceeded` | 直接展示服务端 `error.message`（含上限与「明天 00:00 恢复」） |
| `5xx` / 超时            | 既有降级路径                                                 |

两个客户端本来就优先展示服务端 `error.message`，所以 Step 2 前端**零改动**，也没有触发视觉基线。

### 8.3 三层回滚（按代价从小到大）

1. **只关配额**：`PERSIST_AI_DAILY_LIMIT=0` → 重启，门仍生效。
2. **只关凭据门**：`PERSIST_AI_GATE=off` → 重启，立刻回到 11-16 行为，不必回滚代码、不必回滚 APK。
3. **回滚代码**：换回 `dist.old` 或备份包。**migration v3 不必回滚**——旧代码不读 `ai_usage` / `ai_calls`。

### 8.4 生产操作规则（沿用，未变）

1. 任何后端、Nginx、systemd、env、安全组或静态包变更，先获用户明确授权。
2. 变更前先备份并验证可读。
3. 不在服务器上构建前端（2C2G 容易 OOM）。
4. 后端部署必须同时包含 `server/dist`、`server/package.json`、`shared/dist`、`shared/package.json`。
5. 不重启 `persist-server`，除非改动要求或健康检查异常。
6. 不删除任何回滚源。
7. 不输出真实公网 IP（仓库只写 `121.196.*.*`）。
8. **不要用 `kill %1`**：非交互 ssh 没有作业控制，会杀不掉进程并占端口，导致「配了正确凭据却 401」。用 `P=$!`，收尾 `ss -ltnp` 确认端口释放。

## 11. 已知风险与限制

### 11.1 安全

- 凭据是**静态 PSK 内联在 APK**：包被提取即可复用。当前靠「100 次/天 + IP 限流 + 可轮换」兜底，不是强身份。
- `k1` 明文只在 `app/.env.mobile.local`（gitignore），哈希在本机 `server/.env` 与生产 `/etc/persist/server.env`。轮换必须多 key 并行。
- CORS 只约束浏览器，从来不是鉴权；真正的门是 `PERSIST_AI_GATE`。
- `api/v1/*` 仍是设备令牌，没有用户密码体系（产品决定，不是缺陷）。

### 11.2 数据

- 同步副本不是备份；整库快照不能按账号裁剪，多账号同库时删除账号会被 409 保护挡住。
- 恢复对象是整个 SQLite 文件。
- 生产 5 份快照里，11-14/15/16 三份对应空库（11-17 才有真实数据），恢复前必须核验内容。

### 11.3 合规与发布

- 备案号未下发 ⇒ 不得用域名对外提供服务，不得宣称「已上线」。
- 生成式 AI 专门备案 / 安全评估未完成。
- IP 直连 + cleartext 只适合内部调试。

### 11.4 运维

- 2C2G，不在服务器构建前端。
- SQLite WAL，需持续观察磁盘与锁；当前磁盘 13.6%。
- Node 内置 SQLite 仍打印实验性警告，属预期。

### 11.5 本轮新增的诚实缺口

- **配额路径尚未被真实请求验证**：`ai_usage` 仍为 0 行。下一次真机用 AI 后要回查 `ai_usage` / `ai_calls` 是否按预期落行。
- Step 1 的真机验证是在 `enforce` + Step 2 代码上线前完成的；Step 2 上线后只做了临时实例验证，没有再做一轮真机。

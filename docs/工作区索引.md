## 1. 一句话看懂

一个**单用户个人自用**产品（记录 → AI 复盘）的完整仓库：**一个 React 客户端 + 一个 Fastify 服务端 + 一套共享契约**，
外加**网站设计层**（落地页 / 介绍首页 / OG 卡 / 开场动画）与**部署运维层**（备案 / 域名 / HTTPS）。
2026-11-27 起站点**已正式上线**（HTTPS + 域名 + 备案号页脚三件套齐备）。

## 3. 数据流与边界

| 边界 | 方向 | 说明 |
| --- | --- | --- |
| `landing → app` | 单向跳转 | `home.html` 的 demo / guest 入口 |

| `deploy/site-info.json → 三端` | 构建期内联 | 静态页 + React 端共用 `site-info-core.mjs` |

## 6. 变更纪律

1. **不要新增「第 N 版总结」**——会立刻过期。新增文档前先确认它能不能归进现有某一份。
2. **状态数字只在一处维护**：基线数字以 `HANDOFF.md` §2 为准；本文只放**结构**与带日期的快照。
3. **文档与代码同批更新**：改了行为就改对应事实源，不留「下次再说」。
4. **过期段落标明留档**，不静默删除历史决策（删了 git 里也查得到，但会失去「为什么」）。
5. **提交粒度**：`feat(...)` / `fix(...)` / `docs(...)` / `test(...)` / `chore(...)`。
6. **改动前先读**本文 §2 确认归属——**避免改动无关文件**是硬要求，不是偏好。

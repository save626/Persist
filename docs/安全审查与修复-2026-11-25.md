## 2. 生产凭据轮换（已闭环）

### 2.1 关键事实：DeepSeek 旧模型名已停用

官方文档（api-docs.deepseek.com）当前只在售 `deepseek-flash` / `deepseek-v4-pro`；
`deepseek-chat` / `deepseek-reasoner` 已不在列表（第三方记录 2026-07-24 停用）。
**换 key 必须同步改模型名**，否则新 key 也一样失败。本次生产与本地默认值均已切 `deepseek-flash`。

### 2.2 轮换流程与证据

1. 用户创建新的 DeepSeek key（明文只存密码管理器，**从未进入对话 / 仓库 / shell 历史**）。
2. 本机 `C:\Users\save\dskey.txt` 一次性文件 → scp 到 `/tmp/persist-key-20261125.txt` →
   服务器 Python 脚本读文件替换 env 的 key 行（key 不进命令行参数）→ `shred -u` 删除临时文件。
   Windows Terminal 右键 = 复制而非粘贴，`read -s` 交互粘贴多次失败，故改用文件传递。
3. 备份 `/etc/persist/server.env.bak.20261125`；模型名 sed 改为 `deepseek-flash`；权限 600 root:root。
4. 重启 `persist-server`（重启瞬间 nginx 80 曾 502，是进程尚未 listen 的时序问题，1 秒后恢复）。
5. **验证四层**：

| 层 | 结果 |
| -- | ---- |
| key 哈希对比 | `edaffc95ec5e`（旧）→ `09ca1abf3473`（新），全程未回显明文 |
| `/api/health` | 200 / `ai:deepseek` / `db:ok`（只能证明 env 有值，**不能证明 key 有效**） |
| 直连 `api.deepseek.com/chat/completions` | **HTTP=200**，模型 `deepseek-flash`，返回 "OK" |
| 端到端 `ai_calls` | id=25：`result=ok / http=200 / deepseek-flash / 758+957 tokens / key_id=user:usr_*` |
| 旧 key 作废确认 | 用户删旧 key 后直连返回 **HTTP 401**（新 key 仍 200） |

### 2.3 设备令牌 `pst_` 轮换

旧令牌曾走公网明文 HTTP，按已泄露处理。用户已在 APK 完成「吊销本机 → 恢复码重绑」。
服务器实证：旧设备 `dev_5PpUrrilveYL` 已吊销；新设备 `dev_GWIXKOLBCuxT` 18:49:34 创建、

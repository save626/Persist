## ⚠️ 2026-11-20 更新（第五轮）：落地页取消直达产品的入口

用户指示：「落地页不要有直接跳转进产品的入口『立即体验』，只能在产品介绍首页才能进入产品。」

**已落地**：`landing/index.html` 的「立即体验 → `/app/?mode=demo`」已删除。
两个 CTA 现在都指向介绍首页，但**落点不同**（不是两个一模一样的按钮）：

| 按钮 | 文案 | 目标 |
| ---- | ---- | ---- |
| 主 | 看看它能做什么 | `home.html` |
| 次 | 先看一段解读 | `home.html#story`（直接落在「一天结束时的 AI 解读」那段） |

note 小字同步改为「不用注册。数据默认只存在你自己的设备上。」，
与首页 `#trust` 段的「默认只存在你自己的设备上」同源
（原句提到「演示数据」，但落地页已无演示入口，会指错方向）。

**为什么这条值得写成硬约束**：落地页是**第一个**看到的产品界面。
它若能一步跳进产品，介绍首页就失去了「先讲清楚再进产品」的意义 ——
而这正是本次重做的初衷。顺手加个「立即体验」是最容易被无声破坏的地方：
不报错、不崩，只让叙事顺序悄悄倒过来。

**已落成断言**：`scripts/check-landing.mjs` §0 段静态扫全部 `href`/`src`，
出现任何 `/app/` 直接判失败；CTA 链接必须全部以 `home.html` 开头。

> 本方案 §3.1.2 那张「主 CTA `先看演示` → `/app/?mode=demo`」的表是
> **介绍首页**的文案规格，不适用于落地页 —— 落地页已改为科技展示型。

用户指示（引用）：

> 「`eyeTutorial-replica/web/index.html` 这个 html 文件是对 GitHub 里 eyeTutorial 仓库所展示的效果
> 进行的 html 版复刻，这才是我想要的入场动画的效果。在黄色瞳孔逐渐扩大开后不再进入他的那个心形界面，

> 展现不出原版仓库里所复刻的 py 文件的效果。你现在根据这个 html 文件，按照我刚才的设想进行融入改进。
> 使其通过域名或 ip 进入后先进入入场动画，随着入场动画的逐渐展现进入落地页。」

**已落地**：落地页开场整段换成 **eyeTutorial 的字符画眼睛**（第三轮的 SVG 眼睛已删除），
并把观感**对齐到 Python 原版**，瞳孔铺满后直接进落地页（无星云、无心形）。

#### 来源是三层链路，不是单仓库

| 层 | 位置 | 说明 |
| --- | --- | --- |
| 上游 | `iremcnar/eyeTutorial` | 原始 Python ASCII 艺术，**未声明许可证** |
| 本地复刻 | `D:/Work/geo-web/eyeTutorial-replica/` | `eye_ascii/` 包 + `preview.py`，与上游逐帧一致 |
| Web 移植 | `third_party/eyetutorial-replica/engine.js` | 同一套数学，**逐字节复制不改** |

引擎经 `scripts/inline-intro-engine.mjs` 原样内联进 `landing/index.html`（单文件零外部请求不变），
`--check` 可校验内联块与源文件一致。

#### 「字符过于密集」的定位结论

逐项拆下来，**四个成因全在调用侧，不在引擎里**（引擎与 Python 原版逐帧一致）：

| 成因 | 修法 |
| --- | --- |
| 字符格取错（8×17 / 44 行） | 换成原版实测的 **8×15 / 30 行**（`78×30` 网格） |
| 字体加 `bold` | 去掉粗体（笔画粗一倍 → 格间细缝被糊掉） |
| 字号按格高算 | 改成 **格宽 × 1.75**（Consolas advance ≈ 0.55em） |
| 配色把原版的 `×1.15` 乘两次 | 引擎输出的 `q` 已含那一次，不能再乘 |

外加一个**隐藏元凶**：差量重绘只画新字符、**不擦旧字形**，
旧字符残笔会一层层堆积（推进到瞳孔铺满时整屏金色残影永远擦不掉）。
现在字符一变就 `fillRect` 擦背景色再画。

#### 心形星云怎么彻底关掉

`CFG.T_HEART = 1e6` **只能**让「心形」不出现 —— 云雾本体照样生成，画面里会有一团粉紫圆雾。
真正的开关是**时间线约束**：引擎的云雾条件是 `nebAmt = ease((t − (T_Z0 + 3.5)) / 8.0)`，
只要 **`T_ZD < 3.5`**，推进结束那一刻云雾还没开始生成；收尾段再压到 `nebAmt < 0.008` 就完全干净。

取 `T_Z0 = 4.6 / T_ZD = 3.2 / T.end = 8.5` —— 全程约 8.5 秒：

| 时刻 | 动作 |
| --- | --- |
| 0 – 0.9s | 黑场淡入，只看得到皮肤纹理 |
| 0.9 – 3.3s | 眼睑睁开（带回弹），琥珀虹膜与瞳孔露出 |
| 4.0s | 眨一次眼 |
| 4.6s | 镜头推进瞳孔（指数缩放 1 → 21 倍） |
| 6.9s | 瞳孔铺满，切到深蓝黑星空 |
| 8.5s | 交棒：此刻才开始写手写标题 |

#### 验收方式变了：从「看截图」到「对着原版量」

`scripts/check-landing.mjs` §6 已重写，断言从「SVG 眼睛尺寸」换成：

- 网格必须是原版的 `78×30`、字符格比例 `8:15`
- **疏朗度**：画面近黑占比要落在原版区间（实测 77% vs 原版 75%）
- **无残影**：推进后画面亮像素占比 < 12%（差量重绘漏擦旧字形就会在这里露馅）
- **无星云**：推进后粉紫像素 < 3000
- 心形已禁用、总时长 ≈ 8.5s、交棒后标题画完

## ⚠️ 2026-11-20 更新（第七轮）：灰蓝统一 + 满屏 3D 粒子流星雨 + 点击才进落地页

用户指示（引用）：

> 「整体的入场动画效果我很满意，但是我有一个问题，为什么不可以铺满整个浏览器，

> 去掉落地页的流星雨效果。这个入场动画和所展现的字符色调以及流星雨效果能不能改成灰蓝，
> 和整体的产品色调做统一，背景页也进行统一」

**已落地（4 项）**：

1. **交棒段满屏**：6.9s 瞳孔铺满后，78×30 的字符画布淡出，
   独立全屏 canvas `#introMeteor`（= 视口尺寸，实测 1440×900）淡入，
   铺满整个浏览器视口 —— 眼睛阶段仍保持原版字符格比例（满屏放大会让字符显笨）。
2. **满屏 3D 粒子流星雨**：深度 `d` 同时调制速度 / 拖尾长度 / 线宽 / 亮度，
   远小慢暗、近大快亮；另加一层视差深空星点。所有轨迹从画外左上同一辐射点发出。
3. **点击才进**：8.5s 后停在粒子层，显示「点击任意位置进入」提示；
   点任意位置（或 Enter/Space）才淡出开场、触发手写标题。**不再自动交棒**。
   右下角「跳过开场」在等待态自动淡出（语义重复）。
4. **灰蓝统一**：字符色从原版琥珀改为亮度映射的灰蓝色阶

   intro 背景从偏青的 `#1d3c4f` 改为中性深灰蓝；
   **落地页的常驻流星雨 canvas 删除**（`sky` 元素 + A 段脚本），落地页是一张安静的浅灰蓝纸。

疏朗感消失。所以眼睛阶段居中留边；满屏只在瞳孔铺满后的粒子层实现。

**验收脚本变化**（`scripts/check-landing.mjs`）：
- 落地页 6 视口：流星雨断言 → 「不得有 `#sky` canvas」
- 减动效：画布非空断言 → 标题可见 + 终态
- 动效开关：帧数冻结断言 → 标题终态 + 状态恢复（落地页已无常驻 rAF）
- 开场段：新增粒子层铺满、灰蓝零暖色、等点击不自动交棒、点击后交棒的断言

## ⚠️ 2026-11-20 更新（第八轮）：落地页 Vue3 + Three.js 化

**用户诉求**：调整入场动画与流星雨的整体色调/背景/透明度/发光强度与落地页及产品介绍首页统一；

用 AdditiveBlending 叠加发光、简单材质几何、不写复杂 shader。

**决策过程**：先就三处冲突征询用户 —— ① 技术栈落地方式选「Vite 构建仍出单文件」
（保住零外部请求/离线/部署路径不变，代价 gzip 34 KB → 200 KB）；② 触发时机选「4.6s 立即切粒子」；
③ 色调统一选「只统一色相、入场保持深底」（浅底上 AdditiveBlending 发光不可见）。
用户另选「整个落地页 Vue3 化」。

**落地要点**（详见 `landing/README.md` §2.0/§2.1/§2.1b）：
- 源码 `landing-app/`，`landing/index.html` 为构建产物；Vite SSR 预渲染保住无 JS 可读。
- `MeteorField.js`：正交相机 + 三层 Points（远/中/近不同 size/亮度/速度）+ 拖尾点，
  AdditiveBlending 叠加发光，PC 叠 UnrealBloomPass；无自定义 shader。
- 移动端三重检测 → 粒子 520→200、生成率 66→30、关 Bloom、DPR 上限 1.5。
- visibilitychange 暂停/恢复 rAF；dispose() 释放全部 GPU 资源；关闭按钮可见。
- 4.6s 切粒子（原 6.9s）、6.4s 等点击（原 8.5s）。

**验收**：`check-landing.mjs` 新增 Three.js/WebGL、PC/移动分流、可见性暂停、关闭按钮四组断言；
像素校验从 canvas 2D 改为离屏 RenderTarget 采样（`__persistIntroState().meteorPixels`）。

## 0. 先说结论：现有三件套的 5 个硬伤

推倒重做的理由不是「做得不够好」，而是**它按开发者视角设计，目标是 2026-11-19 之前**
的目标用户不是普通用户。

| # | 硬伤 | 证据 | 对普通用户的伤害 |
| - | ---- | ---- | ---------------- |
| 1 | **落地页首屏是 `Hello world` + 全屏星空** | `landing/index.html` 第 214 行 `<textPath>Hello world</textPath>` | 这是开发者暗号。陌生人 3 秒内不知道这是干什么的，也不知道该点什么 |
| 2 | **首页是"产品说明书"结构**，价值主张藏在 hero 副标题里 | 9 段：问题→怎么工作→三模块→AI 报告→长期→隐私→适合谁→内测 | 普通用户滚到第 5 段才碰到"AI 报告"，前面 4 屏都在讲产品结构而不是自己的收益 |
| 3 | **首页零真实产品画面** | `home.html` 全篇无 `<img>`，首屏"今日卡片"是纯 CSS 摆的 | 看起来像"概念设计"，不像一个真能用的软件 |
| 4 | **OG 卡文案有一处不准确** | 徽标 `本地优先 · 不上传服务器` | 开启同步后记录会存到服务器，这句话会变成假话——假话比不酷更伤 |
| 5 | **两页视觉语言分裂** | 落地页深空冷蓝 `#05070d` + 星空照片；首页浅灰蓝 `#F4F7F9` + 纯 CSS | 不像一个产品做的两页 |

**重做的目标**：保留现有的工程资产（零外部请求、手写描边动画引擎、星空渲染、对比度门禁、
部署链路），**换掉面向人的那一层**：文案、信息结构、视觉语言、真实产品画面。

## 1. 产品定位与价值主张（面向普通用户）

### 1.1 一句话定位

> **Persist：把每天的碎片记录，汇成一段你看懂的话。**

不是"记录工具"，不是"AI 助手"，是**"替你把记录变成结论"的那一步**。

### 1.2 三个用户承诺（首屏只讲这三个）

| 承诺 | 用户语言 | 产品事实支撑 |
| ---- | -------- | ------------ |
| **记一处** | 健身、饮食、学习记在同一个地方，不用来回切 | 三模块：`/fitness` `/diet` `/study` |
| **看懂一天** | 晚上不用自己算，有人给你写一段复盘 | 今日简报 + `/reports` 报告页 |
| **看得见变化** | 一周看节奏，一个月看方向，三个月看自己变了没 | 7 / 30 / 90 天窗口 |

### 1.4 差异化与"我们主动不做"

这是普通用户真正会记住的部分，比功能列表更有说服力：

- 不做连续打卡、不做排行榜、不做社交——**断了就断了，不惩罚你**；
- 不给饮食打分、不给训练评分——**只记录，不评判**；
- 不做拍照识别热量、不做医学建议、不做开放聊天——**AI 只在复盘时说话**。

> 保留并升级原方案里最好的一句：**「Persist 不催你坚持，只帮你看清。」**

### 1.5 禁用词表（写文案时的强制替换表）

| 禁用 | 替换成 |
| ---- | ------ |
| RAG / 检索增强 / 知识库 | 「根据你的记录算出来的」 |
| Agent / 模型调度 / 推理链 | 「AI 帮你写解读」 |
| Token / 上下文窗口 / 配额 | 「用量」「限制」 |
| 向量 / Embedding / 相似度 | 「按你的记录找出来」 |
| 本地优先（对普通用户） | 「记录先存在你自己的设备上」 |
| Schema / IndexedDB / 同步协议 | 「存在你手机里」「可以同步到你自己的服务器」 |

> 技术术语**允许**出现在 §3 第 10 段（技术细节，折叠），那是给 interested people 的。

### 1.6 与现网事实的对齐（防止写出产品做不到的东西）

| 事实 | 来源 | 对文案的约束 |
| ---- | ---- | -------- |
| 网页端只允许 `demo` / `guest` 两种模式，**网页上没有真实 AI** | `app/README.md`、HANDOFF §2.3 | 首页不能写"打开网页就能用 AI"；演示入口要说清"预置数据 + 预生成解读" |
| 完整产品只在手机 `build:mobile` 包（默认 owner） | 同上 | FAQ「手机上能用吗」必须区分两端 |
| 同步**默认关闭** | `app/README.md` §同步 | 隐私文案不能说"绝不上传"，要说"默认不上传，开启同步后存到你自己的服务器" |
| AI 调用只记时间/接口/token，30 天删除；分析归档 365 天 | `home.html` 现文 + HANDOFF | FAQ 给准确保留期，不含糊 |
| 注册已关闭（生产上限 1） | HANDOFF §5.1 | 落地页 CTA 只能是「看演示 / 自己试试」，不能有「注册」 |
| 备案号未下发 | `deploy/site-info.json` | 页脚保留占位注入，**不得编造**；卡面不放备案号 |

## 3. 逐模块：文案 / 内容 / 交互 / 动效

### 3.1 落地页 `index.html`

#### 3.1.1 手写笔迹（新核心资产）

| 项 | 方案 |
| -- | ---- |
| 内容 | **「看清自己」**（4 个汉字） |
| 实现 | **手绘矢量笔画路径**（`<path>` + `stroke-dasharray` 逐笔书写），**不依赖任何字体** |
| 为什么不用系统手写体 | `Sacramento / Lucida Handwriting / Segoe Script` 只覆盖拉丁字母；中文会 fallback 成系统黑体，"手写感"直接归零 |
| 为什么不用 webfont | 硬约束：零外部请求 |
| 时长 | 4 字共 ~40 笔，单字间隔 120ms，整段 ≈ 3.2s（比原 4.4s 更短，留给用户看内容的时间） |
| 笔尖 | 沿当前笔画 `getPointAtLength` 跟随的小光点（保留现有实现） |
| 降级 | `prefers-reduced-motion` → 直接显示终态；SVG 不可用 → 显示同名 HTML 文本 |
| 风险 | **本方案最高风险项**：需逐字绘制 40 条笔画路径，建议单独排期、单独验收 |

> **备选（工期紧时启用）**：手写体只写拉丁品牌名 `Persist`（5 笔以内，零额外工作），
> 中文主张用系统无衬线大字排版。视觉损失：品牌手写感弱化，但 3 秒看懂的目标照样达成。
> **决策点见 §5-Q1。**

| 05 | 每月 / 每季 | `看自己变了没有` | 三个月前和现在，究竟差在哪。 |

视觉：横向时间轴（移动端纵向），节点为圆点 + 细线连接，**当前步用强调色**。
动效：进入视口时线条按步序"生长"（`stroke-dashoffset`，总 0.9s）。

#### 段 5｜体验案例（普通人能看懂）

标题：`看看一天结束的时候，会看到什么。`
副标题：`下面是一位上班族的一整天。内容为示例。`

结构：左 = 当天的三条真实记录（时间戳 + 内容）；右 = 晚上的一段解读。

> **示例解读（示例文案）**
> 「今天该做的三件事完成了两件：训练和复习，饮食那条还没记。
> 蛋白质 96 克，比这一周的平均多了 12 克，主要来自晚餐。
> 连续第三次在训练日漏掉晚餐记录——不影响训练，但晚上容易饿。
> **明天先做一件：训练后补一顿有蛋白的晚餐。**」

关键补充（诚实）：`解读里的每个数字都能点开，回到那条原始记录。数字是记录算出来的，不是 AI 猜的。`

视觉：对话式卡片（不是聊天框——避免让人以为是聊天机器人），右侧解读卡带"依据"角标。
动效：逐条淡入（错峰 100ms），无打字机效果（打字机 = 假进度，误导用户）。

#### 段 6｜长期变化

标题：`你今天记的，不是给今天看的。`

| 尺度 | 标题 | 说明 |
| ---- | ---- | -------- |
| 这一周 | `看出节奏` | 哪几天练了，哪几天断了，一周的起伏。 |
| 这个月 | `看出方向` | 重量、热量、时长，往上还是往下。 |
| 这三个月 | `看出变化` | 三个月前和现在，究竟差在哪里。 |

收尾金句：**`Persist 不催你坚持，只帮你看清。`**

#### 段 7｜信任与特色

标题：`你的记录，是你的。`

| 要点 | 文案 |
| ---- | ---- |
| 记录先存在你的设备上 | 写下来的东西先存在你自己手机 / 浏览器里。同步默认是关的；开了之后，副本也只存到你自己搭的服务器上，删账号会一起清掉。 |
| 数字不是 AI 猜的 | 报告里的每个数字都由你的记录算出来，每句话都能点回原始记录。AI 不下结论，只负责把它写成一段话。 |
| 离线也能记 | 断网、服务器关着，照样能记。写完先落在本地，联网了再同步。 |
| 没有观众 | 没有社交、没有排行榜、没有陌生人看你的记录，也没有连续天数。 |

#### 段 8｜适合谁 / 不适合谁

**适合**：
- 你已经在记，只是记在了三个地方；
- 你想知道"这三个月到底有没有变化"；
- 你不想被连续天数绑架。

**不适合**：
- 想要社交排名的人；
- 想拍照自动算热量的人；
- 想让 AI 给训练 / 饮食方案的人。

补充一行：`另外几件我们主动不做：不做连续打卡和排行榜，不做社交，不靠拍照识别食物，不给医学建议，不做开放聊天。AI 只在复盘时说话。`

#### 段 9｜FAQ（6 问，用 `<details>` 折叠）

| 问 | 答 |
| -- | -- |
| **怎么用？** | 打开就是今天页：先定今天的三件事，白天随手记，晚上看一段复盘。不用注册也能试——「先看演示」是带样例数据的只读版本，「自己试试」是空白开始。 |
| **收费吗？** | 现在是内测，演示和体验都免费。正式价格还没定，定下来会提前告诉你，不会突然开始收费。 |
| **我的记录安全吗？** | 默认只存在你自己的设备上。同步默认关闭；开启后副本存到你自己搭的服务器，删除账号会连服务器副本一起清掉。设置里可以随时导出全部记录，也可以一键清空本机。 |
| **手机上能用吗？** | 完整产品在手机 App 上（Android 内测版）。网页目前提供"演示"和"空白体验"两种，数据都留在浏览器里。 |
| **需要一直联网吗？** | 不需要。写下来的东西先落在本地，服务器不可用也不影响你记录。 |

> **诚实性检查**：Q2「正式价格还没定」是当前真实状态——不得写成「永久免费」。
> Q3 不得写「绝不上传服务器」——开启同步后会上传到用户自己的服务器。

#### 段 10｜技术细节（折叠，默认收起）

标题：`技术细节（给 interested people）` · 说明：`这一段可以跳过。`

内容（每条 2–3 行，用普通人也能读懂的句子，技术名词加括号）：

- **记录存在哪**：先写进你自己的浏览器 / 手机本地存储（IndexedDB），服务器不可用时照常记录；同步是可选开关，默认关闭。
- **AI 怎么保证不乱说**：先由服务端按 7 / 30 / 90 天窗口把记录汇总成一份"事实包"，模型只读这份事实包写文字；正文出现的每个数字必须能在事实包里找到，否则整份报告判为无效、不入库。
- **接口安全**：AI 接口需要服务端签发的凭据，带每日次数与用量上限、IP 限流、审计留痕（只记时间、接口和用量，不存对话内容，30 天后删除）。
- **数据保留**：分析归档保留 365 天；同步副本随账号删除；本机数据可单独清空。
- **可离线**：页面与记录不依赖外网资源，无 CDN、无第三方字体、无统计脚本。

## 4. 前端落地建议

### 4.1 视觉方向

| 维度 | 决定 | 说明 |
| ---- | ---- | -------- |
| 底色 | 浅色为主 `#F7F9FB`，卡片 `#FFFFFF` | 与首页统一；落地页星空保留但整体提亮 |
| 强调色 | 青蓝 `#2E7FA8` / 深蓝 `#1F5F86` | 仅用于非文字装饰与图标；文字另用 `--accent-ink` |
| 墨色 | `#10161C` / 次级 `#48545F` / 弱化 `#6B7783` | 对比度门槛：正文 ≥ 4.5，图形 ≥ 3.0（沿用现有 22 组门禁） |
| 圆角 | 卡片 20px / 控件 12px | 比现版更"软"，接近 Apple |
| 阴影 | 极浅、大扩散、低透明 | 不用重投影 |
| 字体 | 系统栈：`-apple-system / "PingFang SC" / "Noto Sans SC" / system-ui` | 零外部请求（硬约束） |
| 字号 | H1 `clamp(32px,5.4vw,56px)`；H2 `clamp(24px,3.2vw,36px)`；正文 15–16px / 行高 1.85 | |
| 字距 | 标题 `-.02em`；eyebrow `.18em` | |

### 4.2 动画选型表

| 技术 | 用在哪 | 为什么 | 降级 |
| ---- | ------ | ------ | ---- |
| SVG `stroke-dashoffset` 逐笔书写 | 落地页手写笔迹（唯一一次） | 手写感的唯一真实实现方式 | 终态直出 |
| Canvas 几何圆弧 + 流星 | 落地页背景 | 已验证可控、可停帧 | 静态帧；`document.hidden` 停 rAF |
| `IntersectionObserver` 揭示 | 首页各段 | 成熟、可降级 | 超时兜底 + 常驻 `scroll`/`resize` 回退 |
| CSS `transform` / `opacity` | 全部过渡 | 只触发合成，不卡顿 | `prefers-reduced-motion` 全量直出 |
| `stroke-dashoffset` 时间轴 | 首页 5 步时间线 | 一次性的"生长"感 | 直接显示 |

**一律不用**：视差滚动、FLIP 布局动画、`filter: blur()` 大面积动画、无限循环动画、
鼠标跟随、视差图片、canvas 粒子背景。

### 4.3 炫技点放哪里（3 处，其余全克制）

1. **落地页手写笔迹**（第一屏，2–3 秒，一次性）—— 品牌记忆点；
2. **落地页星空**（背景常驻，但降配降亮）—— 氛围，不抢内容；
3. **首页时间轴生长 + 真机截图浮起**（滚动到时各一次）—— 解释结构。

### 4.4 必须克制的 7 条

1. 首屏不放任何"技术名词"；
2. 不做弹窗、不做自动轮播、不做浮窗提示（现版 toast 只用于入口异常，保留）；
3. 不做连续循环动画（除呼吸类微动，且幅度 < 5%）；
4. 不做鼠标跟随、粒子、视差；
5. 一屏只有一个主角（一张截图或一个视觉），不做三张图并排抢焦点；
6. 所有动效时长 ≤ 1s，滚动揭示 ≤ 0.8s；
7. 任何装饰都不得压住或压暗正文（对比度门禁 22 组继续跑）。

### 4.5 移动端适配

| 项 | 规格 |
| -- | ---- |
| 首屏 | ≤ 100dvh 内可见标题 + 主 CTA；星空层降为纯渐变底 + 少量星点 |
| Canvas | DPR 上限 1.5（桌面 2）；星轨数量 ×0.5；流星 6 颗；`prefers-reduced-motion` 静态 |
| 布局 | 三栏 → 单栏；时间轴转纵向；FAQ 原生 `<details>` |
| 触控 | 可点元素 ≥ 44×44px；不依赖 hover 才有信息 |
| 图片 | 真机截图 `loading="lazy"`，宽度属性写死防抖 |
| 降级 | 无 JS 时首页全部内容可读（`<details>` 原生展开）、落地页显示 HTML 文本 + 按钮 |

### 4.6 性能预算

| 项 | 预算 | 现状 |
| -- | ---- | -------- |
| `index.html` gzip | ≤ 16 KB | 10.4 KB |
| `home.html` gzip | ≤ 26 KB | 12.1 KB |
| OG 卡 | ≤ 60 KB | 44 KB |
| 星空资源 | ≤ 2.5 MB（建议 7 档 → 4 档，q84→q78） | 5.4 MB |
| 真机截图（4 张 WebP） | ≤ 360 KB 合计 | 新增 |
| 首屏 LCP | ≤ 1.5 s（4G 模拟） | 未测 |

### 4.7 可访问性

- 焦点可见（`:focus-visible` 2px + 3px offset）、键盘可达全部 CTA；
- `<details>` 做 FAQ 原生折叠，键盘 / 读屏可用；
- 图片 `alt` 写人话，不写文件名；
- 动效尊重 `prefers-reduced-motion`；
- 对比度 22 组门禁继续跑。

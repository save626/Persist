## 1. 入口与边界（不可回退）

```text
域名 / IP
  └─ /                  落地页（开场动画 → 落地页主体）
       └─ home.html      产品介绍首页 —— 唯一的产品入口
            ├─ 查看演示 → /app/?mode=demo
            └─ 自己体验 → /app/?mode=guest
产品内「返回首页」→ home.html
完整产品 → 作者自有移动端 App（USB 安装 build:mobile 包）
```

**硬约束**：

1. **落地页不得有任何直达产品的入口**。原「立即体验 → `/app/?mode=demo`」已删除；
   落地页两个 CTA 都指向 `home.html`（主 → 首屏，次 → `home.html#story`）。
   `scripts/check-landing.mjs` §0 静态扫全部 `href`/`src`：出现任何 `/app/` 直接判失败。
2. 首页只保留 `demo` / `guest` 两个真 `<a href>` 入口，不得新增 `product` / `beta` /
   `blank` / `owner`；关掉 JS 也能进产品。
3. 落地页主体是一张安静的浅灰蓝纸，**没有常驻流星雨**——流星雨只在开场层交棒段出现。
4. 公开页不得触发真实模型调用：示例 AI 内容只能是写死文本并标明「依据当时的记录」。

## 3. 开场动画（最终态）

### 3.1 时间线（唯一事实源：`IntroOverlay.vue` 的 `T` + `EyePlayer.js` 的 `CFG`）

| 时刻 | 动作 |
| --- | --- |
| 0 – 0.9s | 近黑 `#010203` 淡入，只看得到皮肤纹理 |
| 0.9 – 4.6s | 眼睑睁开、眨眼，产品灰蓝三色字符画虹膜 / 巩膜 / 瞳孔露出，**居中** |
| 4.6s | 瞳孔推进开始 → 字符画淡出、星空底图流星雨**逐渐淡入**（与推进同步） |
| 7.8s | 推进结束（`T_Z0 4.6 + T_ZD 3.2`），流星雨完全接管、停眼睛引擎 |
| 7.8s 后 | 界面**不再自动变化**，显示「点击任意位置进入」；点击才交棒落地页 |

`T = { meteor: 4.6, wait: 7.8 }`；`CFG.T_Z0=4.6 / T_ZD=3.2 / T_HEART=1e6 / ZEND=20`。
**不要在 CSS 里写死秒数。**

### 3.2 眼睛层

- **来源**：上游 `iremcnar/eyeTutorial`（Python，未声明许可证）→ 本地复刻包 →
  `third_party/eyetutorial-replica/engine.js`（**逐字节复制，不许改**），
  由 `scripts/inline-intro-engine.mjs` 原样内联，`--check` 可校验一致性。
- **观感基线是 Python 原版** `third_party/eyetutorial-replica/reference/preview-python-original.png`
  的 9 格分镜（t = 2…42s，逐字节副本，SHA256 记在该目录 README）；
  网页复刻版 `web/index.html` 字符过密，不能当基准。
- **疏朗度四要素（都在调用侧，不在引擎）**：网格 78×30；字符格 8×15；字号 `cellW×1.75`、
  不用 `bold`；引擎 `q` 已含 `×1.15` 不得重复乘。另外差量重绘必须先 `fillRect` 擦旧字形。
- **居中（双保险）**：① 画布 CSS `position:absolute; inset:0; margin:auto`
  （父级 flex 对绝对定位子元素无效——这是「偏心」的真正根因，实测原偏差 -146×-36px，
  修后 0×0px）；② 调用侧包装 `renderer.gaze`，推进阶段恒返回 `(0,0)`，消除视线被 z 放大的偏移。
  验收读 `canvasOffsetX/Y` 与 `gazeLocked`。
- **灰蓝三色配色**：深底 `#010203` 保留（流星雨需要深底）；`_palette()` 按「暖度识别虹膜 +
  亮度区分瞳孔/巩膜」把引擎原生 RGB 重映射到产品色同族、但**色相不同**的三色：
  瞳孔 `#1a2a36` / 虹膜 `#467692` / 巩膜 `#c7dae6`。不能退回单蓝亮度映射（会抹掉色相、
  只剩深浅，用户明确抱怨过），也不要恢复琥珀原色。
- **心形星云禁用**：`T_HEART=1e6` 只禁「心形」，云雾本体还需 `T_ZD < 3.5` 的时间线约束 +
  收尾 `ZEND=20` 才彻底干净。

### 3.3 流星雨层（Canvas 2D，服务器部署版样式）

`src/three/MeteorField.js` 逐参数移植 git 历史 `4be7a0f` 的部署版实现，**去掉 "Hello World" SVG 路径描绘动画**：

- **星轨**：几何圆弧绕画面上方极点公转，4 档亮度 × 3 段渐弱，长曝光感。
- **流星**：渐变尾迹（头部高光 → 尾部透明）+ 头部径向光晕，`globalCompositeOperation='lighter'`，
  冷蓝 hue 192–216。
- **第十二轮参数**：PC 上限 **40** 颗（移动端 22）、生成间隔 **0.065s**（约 15.4 颗/s）、
  寿命 **1.6–3.2s**、速度 **300–620px/s**（降速让停留更久）。实测 7.7s 同屏 25–32 颗。
- `useBloom` / `particles` 是兼容字段（语义：「PC 完整效果」/ 流星数组），验收脚本还在读，**别删**。

### 3.4 星空底图（原画质、零裁剪）

- 从 git 历史 `4be7a0f` 取 **`starfield-wide-3000.webp` 原始文件**（3000×1688，1 506 266 B）
  **逐字节 base64**（2 008 386 字符）存 `starfield.datauri.txt`；**零重编码、零缩放、不损失一像素**。
  用户明确「不要压缩画质，哪怕数百 KB」，产物 gzip 因此从 66KB → ~1.59MB，这是已接受的代价。
- `build.mjs` 注入 `:root{--intro-starfield:url("...")}` —— 仍是**单文件 / 零外部请求 / `file://` 可打开**。
- `.intro-meteor` 用 `background-size: cover, cover, 100% 100%`：**零裁剪、零黑边、完整显示**。
  `cover` 会裁掉约 10% 银河与右下静态流星轨迹；`contain` 在 16:10 视口留黑边
  （原图顶边近黑、底边亮蓝，纯色填充无法同时匹配）。两层压暗 scrim 已减淡，星点更亮。

### 3.5 降级、暂停与清理

- **移动端**：UA + `pointer:coarse` + 视口宽度三重判定；星轨 ×0.55、流星上限 22。
- **页面不可见**：`visibilitychange` 暂停渲染，恢复可见后继续。
- **关闭动画按钮**：全程可见，点击立即 `dispose()` 停止并释放画布资源，再交棒；
  等待阶段点击任意位置 / `Enter` / `Space` 也可进入。
- **跳过开场**：`prefers-reduced-motion` / 动效开关关闭 / `?intro=0` / `?still=1` → 完全不播；
  无 JS 时开场层整层 `hidden`；开场期间落地页 `inert`。

## 4. 落地页主体与介绍首页

**落地页**：科技展示型，不是说明书。只留项目名、slogan「把每天的碎片写下来，晚上看懂自己」、
几个关键词；主视觉是内联 SVG 手写标题「Persist」（11 条路径逐笔浮现，字形由 `scripts/wordmark.mjs`
生成，唯一事实源）+ 眼睛标记（入场眨一次眼、虹膜跟随光标微动，偏移 ≤3.2px）。
采用产品令牌：页底 `#F4F7F9`、`--deep #467692`、`--green #6D9FBD`；
`--muted/--faint` 为达标改用 `#55616D/#616D79`。仿真终端与 ASCII 字符流已移除。
不做 Shader / WebGL / 视差堆叠 / 滚动依赖 / 频闪 / 自定义光标 / 数字滚动。

**介绍首页**：12 段叙事（收益 → 能力 → 信任 → 转化），11 个锚点 + 页脚。
技术段固定在第 10 段、默认折叠；17 个禁用词（RAG / Agent / Token / 向量 / IndexedDB /
本地优先…）在第 10 段之前一个都不许出现（`check-home.mjs` 静态断言）。
零 `<img>`（产品画面全是 CSS/SVG 示意）；FAQ 与技术段用原生 `<details>`；
诚实性文案必须在页上（「正式价格还没定 / 暂不开放注册 / 同步默认关闭」）。
21 组色对实测全部达标（正文 4.5 / 图形 3.0）。

细节、调参、踩坑全在 [`bloom/README.md`](../bloom/README.md)。

**四条必须先拍板的冲突**（与本文 §1 硬约束正面相撞）：

1. **单文件 / 零外部请求破功**：MediaPipe 必须同源取 15 MB wasm + 7.8 MB 模型，
   而 `landing/index.html` 现在是 2.1 MB 单文件产物。
2. **`file://` 双击打开失效**：摄像头要安全上下文，这条性质保不住。
3. **首次进入是否弹摄像头权限**：建议沿用本项目的「默认自动 + 按钮开启手势」。
4. **仓库 +22 MB 二进制**：vendored 依赖要不要走 LFS，或者做成首次运行拉取。

## 9. 手势粒子融合工程（第十四轮起，独立工程）

`gesture-particle-fusion-20261121/` —— 与 `bloom/` 并存、**不属于落地页构建链**的独立工程。
它把「花瓣」与「圣诞树」两个题材合进同一个入口：一套 Three.js 渲染、一套手势管线、
两个可切换场景。

```powershell
cd gesture-particle-fusion-20261121
node serve.mjs          # http://localhost:4190
```

### 9.1 当前形态：只剩两个场景

| # | 场景 | 手势映射 | 来源 |
| --- | --- | --- | --- |
| 1 | 花瓣 | 张手/双手拉开 → 满屏散开；捏合/握拳 → 聚成三层花瓣 | `bloom/` 的粒子与着色器 |
| 2 | 圣诞树 | 张手 → 炸散；握拳 → 收树；手左右 → 旋转 | `ZekangLi-Zico/Christmas-Tree` 的 `tree.py` 算法移植 |

- 场景按钮在左下，`1` / `2` 切换；右下角是**颜色选择器 + 开启手势 + 全屏**。
- 手势量统一由 `src/core/gestures.js` 产出（`palm/fist/pinch/spread/fingers/pos/rot`），
  场景只做映射，不再各自解析 21 点。
- 手势延迟：EMA 时间常数 **0.04s**、MediaPipe 检测上限 **30fps**，场景不再叠第二层平滑。

### 9.2 花瓣场景（相对 `bloom/` 的三处变化）

1. **取景回到 bloom 原版**：fov **40** + 按宽高比算距离（`FLOWER_EXTENT 1.45`），
   粒子数 **32000**。此前融合时图省事用全局 fov 55 + 固定 z=4.2、粒子压到 24000，
   花在画面里小了约 1/4、花瓣变薄，看起来"不像三层分层那一版"。
   实测包围盒 **0.605 × 0.859**，与 bloom 的 0.586 × 0.833 对齐。
2. **散开/聚合改成逐粒子推进**：每颗粒子一个 `aDisperse` 进度（0.055–0.13/帧，逐粒子不同），
   由 JS 每帧推进、着色器只读；取代原来"共享阈值 + 瞬间起步"的做法，过渡连续无顿点。
3. **自动循环节奏**（无手势，20 秒一圈）：花停留 7s → 散开 3s → 散着 2s → 聚合 3s → 再停 5s。
   旧版是匀速三角波（0.055/s），0→1 要 18 秒且**从不停留**。

**流星雨 + 星轨回归**：`src/core/meteors.js`（独立 2D canvas，取自 bloom）垫在 WebGL 之下；
该场景的 WebGL 清成透明（`transparentBackground: true`），流星真的在花背后；
切到圣诞树时 `clearAlpha=1` 并摘掉 `body.has-meteors`，不浪费 CPU。

### 9.3 圣诞树场景（`tree.py` 的 WebGL 移植 + 原程序部署）

**原程序已在本机部署**（用户完成）：`sources/06-christmas-tree-zekangli/`
含 `.venv`（pygame 2.6.1）、`requirements.txt`、`run.cmd`、`capture_preview.py`、
参考渲染图 `preview.png`、补丁记录 `PATCHES.md`、上游原文件 `tree.py.upstream`。

两处补丁（`PATCHES.md`）：`pygame.font.SysFont` 在本机对所有字体名抛
`TypeError: expected str, bytes or os.PathLike object, not int`，加 `load_title_font()`
兜底到 `pygame.font.Font(None, size)`；副标题 `"647"` 改为 `CHRISTMAS_SUBTITLE` 环境变量。

运行入口：`sources/06-christmas-tree-zekangli/run.cmd`（或 `.venv\Scripts\python tree.py`）。

Web 端移植保留了 `tree.py` 的全部点生成与配色：70% 螺旋灯带（`h=u^1.6`、9 圈、
`sin((h·5.8+0.15)·2π)` 树枝层次）、30% 蓬松填充（`h=rand^1.9`）、地面 6 圈光环、
空中 1200 星点、树顶隐式方程爱心（`(x²+y²−1)³−x²y³≤0`）与细颈。

本轮在移植版上做了三件事：

| 改动 | 做法 |
| --- | --- |
| **深度排序绘制** | 每 3 帧做一次 256 桶**索引排序**（O(n)），从远到近写入 geometry 的 `index`，Points 按索引顺序绘制 ≈ painter's algorithm；不重排顶点属性 |
| **螺旋/填充拆两个材质** | `spiralMat`(35k) 与 `fillMat`(15k) 各自 `PointsMaterial`，亮度可分别控制：`scene.setBrightness(spiral, fill)`（0–2）；地面/星点/爱心/细颈用加色材质当"光"层 |
| **无手势满屏散开** | 散开目标改为按相机 FOV 与宽高比算出的**视口圆盘**（半径盖住四角），16s 周期在"树 ↔ 满屏"往复；旧版只是球壳小范围松动 |

> 已知近似：螺旋与填充是两个 draw call，无法真正交错绘制；现按两层平均深度决定先后，
> 严格 painter's order 需要合并材质（与"亮度分别控制"冲突）。

## 5. 目标部署架构

```text
用户浏览器 / App
      │
      ▼
Nginx（80；备案后加 443）
      ├── /            → 前端静态产物 app/dist（root 目录 /var/www/persist）
      └── /api/*       → 反向代理 127.0.0.1:3000（Fastify）
                              │
                              └── P4 目标：SQLite 文件 /var/lib/persist/persist.sqlite
                                  + 备份目录 /var/lib/persist/backups（见 P4 方案 §11）
                                  （步骤 12 本机实现、步骤 13 加了报告归档表与每日简报 job，**均未部署**；线上仍是步骤 9 版本）
```

约定：

| 项 | 约定值 |
|---|---|
| 前端静态根目录 | `/var/www/persist`（由本地 `app/dist` 上传，`index.html` 在根） |
| 后端进程 | Fastify，监听 `127.0.0.1:3000`，**不直接对外暴露** |
| 后端常驻 | `systemd` 单元 `/etc/systemd/system/persist-server.service`（`Restart=always`，`User=persist`） |
| 服务端环境变量 | `/etc/persist/server.env`，权限 `600`，`DEEPSEEK_API_KEY` 只存在这里 |
| 数据库（步骤 12/13 已实现，**均未部署**） | 生产目标 `/var/lib/persist/persist.sqlite`（目录属主 `persist:persist`，`0700`）；本机默认 `server/data/persist.sqlite`，`DB_PATH` 可覆盖。**schema 版本 2**（`analysis_reports` / `job_runs` 由启动迁移自动建表） |
| 前端 API 前缀 | 相对路径 `/api`（**绝不写死 IP / 域名**） |

### 5.1 由服务器规格推出的 7 条硬规则

1. **不要在服务器上构建前端**：2 GiB 内存跑 `npm ci` + `vite build` 极易 OOM。本地 `npm run build` 后上传 `app/dist`，服务器只跑 Nginx + Fastify（常驻 ≈100–150 MB）。
2. **SPA 深链必须回退**：`/reports`、`/plans` 直接刷新要被 `try_files $uri $uri/ /index.html;` 接住，且 `/api/` 的 `location` 必须排在静态规则**之前**，否则请求会被吞进 `index.html`。
3. **流量计费 → 必须 gzip + 长缓存**：产物为 `index-<hash>.js`（步骤 13 为 628.24 kB / gzip 186.67 kB）与 `index-<hash>.css`（145.40 kB / gzip 24.89 kB）。hashed 资源给 `immutable` 一年缓存，`index.html` 给 `no-cache`，否则每次回访都重新计费。**线上仍是步骤 9 的 `index-DVS7rlR_.js`（567592 B）**，步骤 12 / 13 的前端产物尚未上传（已过 500 kB 警告线，`/plans` 未拆 bundle，属已知问题）。
4. **前端只写相对 `/api`**：同源部署省掉 CORS；本地开发用 Vite `server.proxy` 指向 `127.0.0.1:3000`。这样备案通过、切换域名时前端零改动。
5. **密钥只在服务端**：仓库只提交 `.env.example`；`app/dist` 与 Android 包中不得出现 Key（P3 完成标准之一）。
6. **P4 用 SQLite 单文件库（步骤 12/13 已落地服务端）**：**驱动已拍板——升 Node 22 LTS，用内置 `node:sqlite`**（无 native 编译、无额外系统依赖；`node:sqlite` 要求 Node ≥ 22.5，当前 22.19.0 可用，启动会打印一条 `ExperimentalWarning`，属预期）。备选 `better-sqlite3` 放弃，避免 2C2G 上 `gcc-c++/make/python3` 编译吃内存。P4 终态为 **SQLite 单文件库**（`/var/lib/persist/persist.sqlite`，WAL，随备份直接拷走），**不安装 MySQL / MariaDB**。步骤 12 的服务端代码（`src/db/*`、`/api/v1/*`）与步骤 13 的分析归档 / job（schema **v2**，启动时自动从 v1 迁移）**均尚未部署**：线上仍是步骤 9 的 Node 20 版本，**升级 Node 与部署新版本一起放在步骤 10**。到时要新增 `DB_PATH`、`DB_BUSY_TIMEOUT_MS`、`SYNC_RATE_LIMIT_MAX` 以及步骤 13 的 `ANALYSIS_RATE_LIMIT_MAX`（6）、`ANALYSIS_TIMEOUT_MS`（45000）、`ANALYSIS_MAX_TOKENS`（2600）、`DAILY_BRIEF_ENABLED`（false）、`DAILY_BRIEF_AT`（21:00）等环境变量（P4 方案 §11 + `server/.env.example`），并给 systemd 补 `ReadWritePaths=/var/lib/persist`（现有 `ProtectSystem=full` 下该目录只读）。**报告 365 天保留靠生成时清理，不需要额外定时任务**。
7. **`dnf` 而非 `apt`**：所有安装命令用 `dnf install -y ...`；Alibaba Cloud Linux 3 与 RHEL 9 兼容。

## 8. Nginx 站点配置（IP 阶段；2026-11-04 已按此上线，与服务器实际文件一致）

```nginx
server {
    listen 80 default_server;
    listen [::]:80 default_server;
    server_name _;                     # 备案号下发后改成 wpersist.top

    root /var/www/persist;
    index index.html;

    gzip on;
    gzip_comp_level 5;
    gzip_min_length 1024;
    gzip_proxied any;
    gzip_types text/plain text/css application/javascript application/json application/xml image/svg+xml;

    # 1) API 必须先匹配，否则会被静态规则吞掉
    location /api/ {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header Connection "";
        # SSE 流式输出：关闭缓冲，避免整段回答一次性吐出
        proxy_buffering off;
        proxy_cache off;
        proxy_read_timeout 300s;
        proxy_send_timeout 300s;
    }

    # 2) hashed 静态资源长缓存（文件名带 content hash，可安全 immutable）
    #    注意：只写 add_header，不要再叠加 expires 1y，否则会返回重复的 Cache-Control
    location ~* "^/(assets|design)/" {
        add_header Cache-Control "public, max-age=31536000, immutable";
        access_log off;
        try_files $uri =404;
    }

    # 3) SPA 深链回退
    location / {
        try_files $uri $uri/ /index.html;
    }

    # 4) 入口文件不缓存，保证发版后立刻拿到新的 hash 引用
    location = /index.html {
        expires -1;
    }
}
```

> `proxy_buffering off` 是为 P3 的 SSE 流式准备（`/api/chat`，8b 起真实使用），**不能去掉**；`proxy_read_timeout 300s` 同时覆盖 `/api/report` 的非流式长请求（单次 10–25 s，服务端自身 25 s 超时），两者共用同一个 `/api/` location。
>
> 两个实测坑（2026-11-04）：① `nginx.conf` 自带的默认 server（`server_name _;`）没有 `default_server` 标记，本文件标了 `default_server` 后 `nginx -t` 会报 `conflicting server name "_" ... ignored` 警告，属预期（本文件接管 80），不影响请求；② `add_header` 与 `expires 1y` 同时写在 hashed 资源上会发出**重复的 `Cache-Control`**，因此资源只用 `add_header`、`index.html` 只用 `expires -1`；另外服务端 `X-Accel-Buffering: no` 会被 Nginx 消费，不会出现在客户端响应头里，验证 SSE 是否被缓冲要看事件是否增量到达（首包 0.118 s → 末包 4.215 s）。

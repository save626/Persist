## 5. 目标部署架构

```text
用户浏览器 / App
      │
      ▼
Nginx（80；备案后加 443）
      ├── /            → 前端静态产物 app/dist（root 目录 /var/www/persist）
      └── /api/*       → 反向代理 127.0.0.1:3000（Fastify）
                              │
                              └── P4 目标：SQLite 文件 /var/lib/persist/persist.sqlite
                                  + 备份目录 /var/lib/persist/backups（见 P4 方案 §11）
                                  （步骤 12/13 的服务端已于 2026-11-06 部署：schema v2 + 报告归档表 + 每日简报 job 都在生产；前端产物 2026-11-07 已上传）
```

约定：

| 项 | 约定值 |
|---|---|
| 前端静态根目录 | `/var/www/persist`（由本地 `app/dist` 上传，`index.html` 在根） |
| 后端进程 | Fastify，监听 `127.0.0.1:3000`，**不直接对外暴露** |
| 后端常驻 | `systemd` 单元 `/etc/systemd/system/persist-server.service`（`Restart=always`，`User=persist`） |
| 服务端环境变量 | `/etc/persist/server.env`，权限 `600`，`DEEPSEEK_API_KEY` 只存在这里 |
| 数据库（步骤 12/13 已实现，**2026-11-06 已部署**） | 生产库 `/var/lib/persist/persist.sqlite`（已建，WAL；目录属主 `persist:persist`，`0700`）；本机默认 `server/data/persist.sqlite`，`DB_PATH` 可覆盖。**schema 版本 2**（`analysis_reports` / `job_runs` 由启动迁移自动建表） |
| 前端 API 前缀 | 相对路径 `/api`（**绝不写死 IP / 域名**） |

### 5.1 由服务器规格推出的 7 条硬规则

1. **不要在服务器上构建前端**：2 GiB 内存跑 `npm ci` + `vite build` 极易 OOM。本地 `npm run build` 后上传 `app/dist`，服务器只跑 Nginx + Fastify（常驻 ≈100–150 MB）。
2. **SPA 深链必须回退**：`/reports`、`/plans` 直接刷新要被 `try_files $uri $uri/ /index.html;` 接住，且 `/api/` 的 `location` 必须排在静态规则**之前**，否则请求会被吞进 `index.html`。
3. **流量计费 → 必须 gzip + 长缓存**：产物为 `index-<hash>.js`（步骤 13 为 628.24 kB / gzip 186.67 kB）与 `index-<hash>.css`（145.40 kB / gzip 24.89 kB）。hashed 资源给 `immutable` 一年缓存，`index.html` 给 `no-cache`，否则每次回访都重新计费。**线上现为 `index-F8XZrWTT.js`（628242 B / gzip 186.67 kB，2026-11-07 上传）**（已过 500 kB 警告线，`/plans` 未拆 bundle，属已知问题）；**后端已于 2026-11-06 切到步骤 13 版本**，前端产物上传（步骤 10 第 8 项）已于 2026-11-07 完成（见 §6.1）。
4. **前端只写相对 `/api`**：同源部署省掉 CORS；本地开发用 Vite `server.proxy` 指向 `127.0.0.1:3000`。这样备案通过、切换域名时前端零改动。
5. **密钥只在服务端**：仓库只提交 `.env.example`；`app/dist` 与 Android 包中不得出现 Key（P3 完成标准之一）。
6. **P4 用 SQLite 单文件库（步骤 12/13 已落地服务端）**：**驱动已拍板——升 Node 22 LTS，用内置 `node:sqlite`**（无 native 编译、无额外系统依赖；`node:sqlite` 要求 Node ≥ 22.5，当前 22.19.0 可用，启动会打印一条 `ExperimentalWarning`，属预期）。备选 `better-sqlite3` 放弃，避免 2C2G 上 `gcc-c++/make/python3` 编译吃内存。P4 终态为 **SQLite 单文件库**（`/var/lib/persist/persist.sqlite`，WAL，随备份直接拷走），**不安装 MySQL / MariaDB**。步骤 12 的服务端代码（`src/db/*`、`/api/v1/*`）与步骤 13 的分析归档 / job（schema **v2**，启动时自动从 v1 迁移）**已于 2026-11-06 部署到生产**（Node v22.19.0 + `/opt/persist-next` + `/var/lib/persist/persist.sqlite`，切换停机 482 ms）；**前端静态包 2026-11-07 已换成步骤 13 版**（`index-F8XZrWTT.js` 628242 B）。部署时已新增 `DB_PATH`、`DB_BUSY_TIMEOUT_MS`、`SYNC_RATE_LIMIT_MAX` 以及步骤 13 的 `ANALYSIS_RATE_LIMIT_MAX`（6）、`ANALYSIS_TIMEOUT_MS`（45000）、`ANALYSIS_MAX_TOKENS`（2600）、`DAILY_BRIEF_ENABLED`（false）、`DAILY_BRIEF_AT`（21:00）等环境变量（P4 方案 §11 + `server/.env.example`），并给 systemd 补 `ReadWritePaths=/var/lib/persist`、`ProtectSystem=strict`、`UMask=0027`（原 `ProtectSystem=full` 下该目录只读）；14a 又追加 `DB_BACKUP_DIR`（默认 `dirname(DB_PATH)/backups`）、`BACKUP_KEEP_DAYS|WEEKS|MONTHS`、`DISK_WARN_PERCENT`（`/etc/persist/server.env` 现 24 键，`600 root:root`）。**报告 365 天保留靠生成时清理，不需要额外定时任务**；**备份快照靠 systemd timer**（见 §6.1）。
7. **`dnf` 而非 `apt`**：所有安装命令用 `dnf install -y ...`；Alibaba Cloud Linux 3 与 RHEL 9 兼容。

```nginx
    #    注意：只写 add_header，不要再叠加 expires 1y，否则会返回重复的 Cache-Control
    location ~* "^/(assets|design)/" {
        add_header Cache-Control "public, max-age=31536000, immutable";
        access_log off;
        try_files $uri =404;
    }

    # 3) SPA 深链回退
    location / {
        try_files $uri $uri/ /index.html;
    }

    # 4) 入口文件不缓存，保证发版后立刻拿到新的 hash 引用
    location = /index.html {
        expires -1;
    }
}
```

> `proxy_buffering off` 是为 P3 的 SSE 流式准备（`/api/chat`，8b 起真实使用），**不能去掉**；`proxy_read_timeout 300s` 同时覆盖 `/api/report` 的非流式长请求（单次 10–25 s，服务端自身 25 s 超时），两者共用同一个 `/api/` location。
>
> 两个实测坑（2026-11-04）：① `nginx.conf` 自带的默认 server（`server_name _;`）没有 `default_server` 标记，本文件标了 `default_server` 后 `nginx -t` 会报 `conflicting server name "_" ... ignored` 警告，属预期（本文件接管 80），不影响请求；② `add_header` 与 `expires 1y` 同时写在 hashed 资源上会发出**重复的 `Cache-Control`**，因此资源只用 `add_header`、`index.html` 只用 `expires -1`；另外服务端 `X-Accel-Buffering: no` 会被 Nginx 消费，不会出现在客户端响应头里，验证 SSE 是否被缓冲要看事件是否增量到达（首包 0.118 s → 末包 4.215 s）。

## 5. 目标部署架构

```text
用户浏览器 / App
      │
      ▼
Nginx（80；备案后加 443）
      ├── /            → 前端静态产物 app/dist（root 目录 /var/www/persist）
      └── /api/*       → 反向代理 127.0.0.1:3000（Fastify）
                              │
                              └── P4（未实施）：SQLite 文件 /var/lib/persist/persist.sqlite
                                  + 备份目录 /var/lib/persist/backups（见 P4 方案 §11）
```

约定：

| 项 | 约定值 |
|---|---|
| 前端静态根目录 | `/var/www/persist`（由本地 `app/dist` 上传，`index.html` 在根） |
| 后端进程 | Fastify，监听 `127.0.0.1:3000`，**不直接对外暴露** |
| 后端常驻 | `systemd` 单元 `/etc/systemd/system/persist-server.service`（`Restart=always`，`User=persist`） |
| 服务端环境变量 | `/etc/persist/server.env`，权限 `600`，`DEEPSEEK_API_KEY` 只存在这里 |
| 数据库（P4 才引入，未实施） | `/var/lib/persist/persist.sqlite`（目录属主 `persist:persist`，`0700`） |
| 前端 API 前缀 | 相对路径 `/api`（**绝不写死 IP / 域名**） |

### 5.1 由服务器规格推出的 7 条硬规则

1. **不要在服务器上构建前端**：2 GiB 内存跑 `npm ci` + `vite build` 极易 OOM。本地 `npm run build` 后上传 `app/dist`，服务器只跑 Nginx + Fastify（常驻 ≈100–150 MB）。
2. **SPA 深链必须回退**：`/reports`、`/plans` 直接刷新要被 `try_files $uri $uri/ /index.html;` 接住，且 `/api/` 的 `location` 必须排在静态规则**之前**，否则请求会被吞进 `index.html`。
3. **流量计费 → 必须 gzip + 长缓存**：产物为 `index-<hash>.js`（约 552 kB / gzip 163 kB）与 `index-<hash>.css`（约 137 kB / gzip 24 kB）。hashed 资源给 `immutable` 一年缓存，`index.html` 给 `no-cache`，否则每次回访都重新计费。
4. **前端只写相对 `/api`**：同源部署省掉 CORS；本地开发用 Vite `server.proxy` 指向 `127.0.0.1:3000`。这样备案通过、切换域名时前端零改动。
5. **密钥只在服务端**：仓库只提交 `.env.example`；`app/dist` 与 Android 包中不得出现 Key（P3 完成标准之一）。
6. **P3 期间不引入数据库，P4 用 SQLite 单文件库**：Node 20 没有内置 `node:sqlite`（Node 22.5+ 才有），引入 SQLite 要么升级 Node，要么 native 编译 `better-sqlite3`（需 `dnf install gcc-c++ make python3`，2C2G 上编译会明显吃内存）。P3 的 DeepSeek 代理是无状态转发，**先不落库**。P4 终态已定稿为 **SQLite 单文件库**（`/var/lib/persist/persist.sqlite`，随备份直接拷走），**不安装 MySQL / MariaDB**（2 GiB 内存无必要，且多一个常驻进程与运维面）。**驱动二选一仍待用户拍板**（升级 Node 22 用内置 `node:sqlite` ← 推荐 / 保留 Node 20 用 `better-sqlite3`），决策与影响见 `docs/P4-数据层与AI综合分析设计方案.md` §4 与 §18-1；无论选哪条，服务端都要新增 `DB_PATH`、`DB_BACKUP_DIR` 等环境变量（该文档 §11）。
7. **`dnf` 而非 `apt`**：所有安装命令用 `dnf install -y ...`；Alibaba Cloud Linux 3 与 RHEL 9 兼容。

## 8. Nginx 站点配置草案（IP 阶段，可直接复制到 `/etc/nginx/conf.d/persist.conf`）

```nginx
server {
    listen 80 default_server;
    server_name _;                     # 备案通过后改成 wpersist.top

    root /var/www/persist;
    index index.html;

    gzip on;
    gzip_comp_level 5;
    gzip_min_length 1024;
    gzip_types text/plain text/css application/javascript application/json image/svg+xml;

    # 1) API 必须先匹配，否则会被静态规则吞掉
    location /api/ {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        # SSE 流式输出：关闭缓冲，避免整段回答一次性吐出
        proxy_buffering off;
        proxy_cache off;
        proxy_read_timeout 300s;
    }

    # 2) hashed 静态资源长缓存（文件名带 content hash，可安全 immutable）
    location ~* "^/(assets|design)/" {
        expires 1y;
        add_header Cache-Control "public, max-age=31536000, immutable";
        access_log off;
    }

    # 3) SPA 深链回退
    location / {
        try_files $uri $uri/ /index.html;
    }

    # 4) 入口文件不缓存，保证发版后立刻拿到新的 hash 引用
    location = /index.html {
        add_header Cache-Control "no-cache";
    }
}
```

> `proxy_buffering off` 是为 P3 的 SSE 流式准备（`/api/chat`，8b 起真实使用），**不能去掉**；`proxy_read_timeout 300s` 同时覆盖 `/api/report` 的非流式长请求（单次 10–25 s，服务端自身 25 s 超时），两者共用同一个 `/api/` location。

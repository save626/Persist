### 4.2 备案号下发后怎么对外分享（2026-11-19 写定）

**先厘清概念**：分享卡**不是**一张要被发出去的图片，也不是一个页面。它是**链接的封面**——
别人分享 `https://wpersist.top/` 时，平台爬虫抓页面 `<head>` 里的 `og:*` / `twitter:*`，
把「图 + 标题 + 描述 + 域名」拼成一条卡片。**你分享的永远是链接，卡片是对方那边自动生成的。**
`landing/og/` 只是本机生产这张图的工具目录（设计源 + 预览页），本身永不上线；
唯一对外的产物是 `landing/assets/og-card.png`。

**各平台的实际路径**（微信部分为社区实测口径，官方无公开文档，版本间有出入）：

| 平台 | 操作 | 结果 |
| --- | --- | --- |
| X (Twitter) | 直接粘贴 `https://wpersist.top/` | 自动渲染 `summary_large_image` 大图卡 |
| Facebook / LinkedIn | 同上 | 大图 + 标题 + 描述 |
| 微信 · 聊天 | **不要直接粘网址**（2021 年后微信收回「转发即带卡片」，多为纯文本）。可靠路径：① 扫码打开 → 右上角「···」→ 分享给朋友；② 从「收藏」打开 → 分享；③ 「搜一搜」→ 访问网页 → 分享 | 图文消息卡片 |
| 微信 · 朋友圈 | 从网页右上角「分享到朋友圈」 | **纯文字 + 一张小图**（1:1 中心裁切，见 §4.1 待决项） |

**分享前必须先确认的三件事**：

1. **AI 接口是关着的**——已实测（2026-11-19）：无凭据 `POST /api/chat` 返回 `401 ai_unauthorized`
   （生产 `PERSIST_AI_GATE=enforce` + `PERSIST_AI_KEYS`），`/api/v1/*` 另有设备令牌鉴权。
   **所以「把链接发出去」不会等于「把模型接口开放出去」**，不会被人白嫖 DeepSeek 额度。
2. **页脚有真实备案号**——备案合规要求「页面底部可见」；`deploy/scripts/render-site-info.mjs` 注入后
   两页页脚出现真实编号，**没有编号就不能对外分享**（这是硬门槛，不是建议）。
3. **网页侧零真实 AI**——`/app/?mode=demo|guest` 是零 `/api/*` 的（demo 读预生成快照，guest 走 Mock），
   网页构建解析层拒绝 `owner`。公开面不提供生成式 AI 服务，**不触碰「向公众提供生成式 AI 需专门备案」**；
   一旦让访客触达真实 AI，那条线才成立。

**验证与缓存**：微信按 URL 缓存抓取结果，改图后要换 URL 参数（如 `?v=2`）再分享，否则看到的还是旧卡；
可用第三方预览工具（opengraph.xyz 等）看爬虫实际抓到的 `og:image`。**统一分享 `/`**，
不要分享 `/index.html` 这类别名（微信以实际 URL 为准，会与 `canonical` 不一致）。

**想做「网站内嵌微信分享按钮」**：需要公众号（认证号或测试号）+ 公众号后台把 `wpersist.top`
加进「JS 接口安全域名」+ 服务端签名（JS-SDK）。对个人项目成本偏高，**当前建议不做**，
用上面的「右上角菜单分享 / 发链接」即可。

### 5.1 由服务器规格推出的 7 条硬规则

1. **不要在服务器上构建前端**：2 GiB 内存跑 `npm ci` + `vite build` 极易 OOM。本地 `npm run build` 后上传 `app/dist`，服务器只跑 Nginx + Fastify（常驻 ≈100–150 MB）。
2. **SPA 深链必须回退**：web 深链为 `/app/reports`、`/app/plans`，必须由 `location ^~ /app/ { try_files $uri $uri/ /app/index.html; }` 接住；`/api/` 的 `location` 必须排在静态规则之前，否则请求会被吞进页面。
3. **流量计费 → 必须 gzip + 长缓存**：产物为 `index-<hash>.js` 与 `index-<hash>.css`。hashed 资源给 `immutable` 一年缓存，入口 HTML 给 `no-cache`，否则每次回访都重新计费。**线上 React web 现为 `app/assets/index-B3NNyoQi.js` + `app/assets/index-CrPNl0GG.css`（已按路由分包，主包 394 kB，无 500 kB 警告）**；**后端已于 2026-11-06 切到步骤 13 版本、2026-11-11 部署 `ec8f16f`**（见 §6.1）。
4. **Web 前端只写相对 `/api`**：同源部署省掉 CORS；本地开发用 Vite `server.proxy` 指向 `127.0.0.1:3000`。Android WebView 是例外：页面 origin 固定为 `https://localhost`，`app/src/lib/mobile-api.ts` 仅把相对 `/api/*` 改写到 `.env.mobile.local` 配置的服务器 origin；服务端需允许该 origin（默认已允许，可用 `PERSIST_ALLOWED_ORIGINS` 覆盖）。这只是 CORS，不是鉴权。
5. **密钥只在服务端**：仓库只提交 `.env.example`；`app/dist` 与 Android 包中不得出现 Key（P3 完成标准之一）。
6. **P4 用 SQLite 单文件库（步骤 12/13 已落地服务端）**：**驱动已拍板——升 Node 22 LTS，用内置 `node:sqlite`**（无 native 编译、无额外系统依赖；`node:sqlite` 要求 Node ≥ 22.5，当前 22.19.0 可用，启动会打印一条 `ExperimentalWarning`，属预期）。备选 `better-sqlite3` 放弃，避免 2C2G 上 `gcc-c++/make/python3` 编译吃内存。P4 终态为 **SQLite 单文件库**（`/var/lib/persist/persist.sqlite`，WAL，随备份直接拷走），**不安装 MySQL / MariaDB**。步骤 12 的服务端代码（`src/db/*`、`/api/v1/*`）与步骤 13 的分析归档 / job（schema **v2**，启动时自动从 v1 迁移）**已于 2026-11-06 部署到生产**（Node v22.19.0 + `/opt/persist-next` + `/var/lib/persist/persist.sqlite`，切换停机 482 ms）；**前端静态包此后多次更新，当前为 `index-B3NNyoQi.js`**。部署时已新增 `DB_PATH`、`DB_BUSY_TIMEOUT_MS`、`SYNC_RATE_LIMIT_MAX` 以及步骤 13 的 `ANALYSIS_RATE_LIMIT_MAX`（6）、`ANALYSIS_TIMEOUT_MS`（45000）、`ANALYSIS_MAX_TOKENS`（2600）、`DAILY_BRIEF_ENABLED`（false）、`DAILY_BRIEF_AT`（21:00）等环境变量（P4 方案 §11 + `server/.env.example`），并给 systemd 补 `ReadWritePaths=/var/lib/persist`、`ProtectSystem=strict`、`UMask=0027`（原 `ProtectSystem=full` 下该目录只读）；14a 又追加 `DB_BACKUP_DIR`（默认 `dirname(DB_PATH)/backups`）、`BACKUP_KEEP_DAYS|WEEKS|MONTHS`、`DISK_WARN_PERCENT`（`/etc/persist/server.env` 现 24 键，`600 root:root`）。**报告 365 天保留靠生成时清理，不需要额外定时任务**；**备份快照靠 systemd timer**（见 §6.1）。
7. **`dnf` 而非 `apt`**：所有安装命令用 `dnf install -y ...`；Alibaba Cloud Linux 3 与 RHEL 9 兼容。

## 8. Nginx 站点配置（IP 阶段；2026-11-11 入口路由版，与服务器实际文件一致）

```nginx
server {
    listen 80 default_server;
    listen [::]:80 default_server;
    server_name _;

    root /var/www/persist;
    index index.html;

    gzip on;
    gzip_comp_level 5;
    gzip_min_length 1024;
    gzip_proxied any;
    gzip_types text/plain text/css application/javascript application/json application/xml image/svg+xml;

    # 1) API 必须先匹配，否则会被静态规则吞掉
    location /api/ {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        # 必须用 $remote_addr 覆盖，不能用 $proxy_add_x_forwarded_for 追加：
        # 追加会把客户端自己填的 X-Forwarded-For 保留在前面，后端取最左值
        # 就等于采信了伪造来源，按 IP 的限流可被逐次换头绕过（2026-11-18 修复）。
        proxy_set_header X-Forwarded-For $remote_addr;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header Connection "";
        proxy_buffering off;
        proxy_cache off;
        proxy_read_timeout 300s;
        proxy_send_timeout 300s;
    }

    # 2) ACME HTTP-01 挑战路径（certbot webroot 模式，2026-11-19 新增）
    #    必须用 ^~ 精确前缀，且排在兜底的 location / 之前。
    #    兜底的 try_files $uri $uri/ /index.html 会把挑战令牌回退成落地页 HTML，
    #    验证服务器拿到 HTML 而不是令牌，签发必然失败（2026-11-19 实测确认的坑）。
    #    webroot 目录：/var/www/certbot（与 certbot --webroot -w 参数一致）
    location ^~ /.well-known/acme-challenge/ {
        root /var/www/certbot;
        default_type text/plain;
        try_files $uri =404;
    }

    # 3) 落地页图片资源：hashed/稳定文件长缓存
    location ~* "^/(assets|design)/" {
        add_header Cache-Control "public, max-age=31536000, immutable";
        access_log off;
        try_files $uri =404;
    }

    # 开场手势的 MediaPipe 资源（≈22 MB）：/fusion/ 下只有 .mjs / .js / .wasm / .json / .task。
    # 必须显式给 .mjs 与 .js 正确的 JS 类型 —— Nginx 1.24 的 mime.types 里没有 mjs，
    # 默认落到 application/octet-stream，浏览器会拒绝动态 import()
    # （2026-11-23 部署实测：vision_bundle.mjs 返回 octet-stream，手势必挂）。
    # 这里的 types{} 只覆盖该 location；文件名不带 hash，给 7 天缓存。
    location ^~ /fusion/ {
        add_header Cache-Control "public, max-age=604800";
        types {
            text/javascript   mjs js;
            application/wasm  wasm;
            application/json  json;
            text/plain        txt;
        }
        try_files $uri =404;
    }

    # 4) 两个入口 HTML 不缓存
    location = /index.html {
        expires -1;
    }

    location = /home.html {
        expires -1;
    }

    location = /app {
        return 301 /app/;
    }

    location = /app/index.html {
        expires -1;
    }

    # 5) React web hashed 资源长缓存
    location ^~ /app/assets/ {
        add_header Cache-Control "public, max-age=31536000, immutable";
        access_log off;
        try_files $uri =404;
    }

    # 6) /app/* 深链回退到 React web
    location ^~ /app/ {
        try_files $uri $uri/ /app/index.html;
    }

    # 7) 根路径只回退落地页，不把未知路径误送进 React app
    location / {
        try_files $uri $uri/ /index.html;
    }
}
```

> **本节已于 2026-11-19 版本化**：上面的内容不再只存在于本文散文里，而是落在仓库的 `deploy/nginx/persist.conf`（**唯一事实来源**，与生产 `/etc/nginx/conf.d/persist.conf` 保持一致）。以后改 Nginx 配置的顺序是「改 `deploy/nginx/persist.conf` → 同步到服务器 → `nginx -t` → `systemctl reload nginx`」，不要只改服务器或只改文档。
>
> 备案号下发后还要上线的两份配置（**当前不部署**）：`deploy/nginx/persist-tls.conf`（443 HTTPS + HTTP/2 + OCSP stapling + HSTS）与 `deploy/nginx/persist-redirect.conf`（HTTP→HTTPS 跳转，页面 301、API 308）。两份都已用 staging 演练证书实测通过，详见 §4.1。

> `proxy_buffering off` 是为 P3 的 SSE 流式准备（`/api/chat`，8b 起真实使用），**不能去掉**；`proxy_read_timeout 300s` 同时覆盖 `/api/report` 的非流式长请求（单次 10–25 s，服务端自身 25 s 超时），两者共用同一个 `/api/` location。
>
> 2026-11-11 入口部署后的关键点：`location ^~ /app/` 独立处理 React 深链，根路径不会再把 `/app/...` 误吞成落地页；`/app/assets/` 与根 `/assets/` 都使用 immutable 缓存；`/`、`/home.html`、`/app/index.html` 均不缓存。`nginx -t` 仍会输出既有的 `conflicting server name "_" ... ignored` 警告，属预期。
>
> 两个更早的实测坑（2026-11-04）：① 自带的默认 server 没有 `default_server` 标记，本文件标了 `default_server` 后出现同名警告，不影响请求；② `add_header` 与 `expires 1y` 同时写在 hashed 资源上会发出**重复的 `Cache-Control`**，因此资源只用 `add_header`、入口 HTML 只用 `expires -1`；另外服务端 `X-Accel-Buffering: no` 会被 Nginx 消费，不会出现在客户端响应头里，验证 SSE 是否被缓冲要看事件是否增量到达。
